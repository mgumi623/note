# 病院における議事録AI・音声認識クラウドサービスの導入状況と課題

## 調査概要

2024〜2025年を中心に、日本の病院における議事録自動作成ツールおよびクラウド音声認識サービス（AWS Transcribe、Azure Speech Services、Google Cloud Speech-to-Text など）の活用状況、法的・技術的課題、現場の実態を調査した。

---

## 1. 病院での議事録自動作成・音声認識ツールの普及率と事例（2024〜2025年）

### 全体的な普及状況

日本の病院における音声認識AIの導入は、電子カルテ入力の補助を中心に急速に拡大しており、2024〜2025年には厚生労働省の実証事業も後押しし、「議事録」「カンファレンス要約」「インフォームドコンセント（IC）記録」などの用途にも広がっている。

一方で、議事録作成に特化した導入は、カルテ音声入力に比べてまだ普及途上の段階にある。

|---|---|---|

| AmiVoice Ex7 | 株式会社アドバンスト・メディア | 医療特化の専用音声入力システム |

### 具体的な導入事例

内閣府 SIP「AIホスピタル」モデルとして、音声によるカルテ自動記録システムを導入。全国20病院が横展開準備中で、看護師の患者対面時間が1日あたり18分創出されたと報告されている。単純計算すると、100人の看護師がいれば1日あたり約30時間分の患者ケア時間が生み出されることになる。

**JCHO北海道病院（2025年1月〜）**
プレシジョン社の「今日のAI音声認識」とシーエスアイ社の電子カルテシステム「MI・RA・Is V」を連携。厚生労働省の「ICT機器を活用した勤務環境改善の先駆的取組をおこなうモデル医療機関調査支援事業」に採択された。音声入力と電子カルテの直接連携によりカルテ入力時間の大幅短縮を目指している。

**HITO病院（愛媛県）**
医師全員がiPadを所持し、音声認識ソフトを活用。記録入力時間の削減により、患者のそばにいる時間を増やすという方針で導入。

**大学病院放射線科（複数施設）**
音声認識によるレポート作成導入後、作成時間がキーボード入力時の1/5〜1/10に短縮されたと報告されている。放射線レポートは定型文が多いため、音声認識との相性がよい。

### 議事録・会議記録への活用

カンファレンスやICなどの音声録音・アップロードだけで必要な情報がまとめられた文章が出力される仕組みが普及しつつある。AI要約機能により、後の振り返りや引き継ぎ資料の作成も効率化されている。

**ヨコクラ病院（九州）**
Google の Gemini を活用した音声文字起こしと要約機能を導入し、インフォームドコンセント記載業務の効率が33%向上した。

**九州大学病院**
Gemini による紹介状の要約と標準化を導入し、入院サマリー作成の医師の効率が54%向上した。

**京都大学医学部附属病院（2024年）**
Google Cloud の Vertex AI（MedLM、Gemini 1.0 Pro、Gemini 1.5 Flash）を活用した「CocktailAI」を眼科で開発・導入。バックエンドにフィッティングクラウド社が開発し、医療文書生成の精度を高める仕組みを採用している。

## 2. 音声データの患者情報含有リスクと個人情報保護法の観点

### 音声データは「要配慮個人情報」に相当するリスクがある

個人情報保護法の観点から、診察室・手術室・カンファレンス室での音声データは以下のリスクを持つ。

- **患者氏名・年齢・病状・治療内容を含む**：音声の内容が個人情報に直結する
- **手術動画・録音データは「個人情報」に該当する**と個人情報保護委員会が明確にしている
- 第三者（クラウド事業者含む）への提供には**本人の同意が必要**
- 漏えい・不正アクセスが発生した場合は**個人情報保護委員会への報告と本人への通知義務**がある

### 医療機関に特有の規制

医療機関は一般企業とは異なり、「医療・介護関係事業者における個人情報の適切な取扱いのためのガイダンス」（個人情報保護委員会・厚生労働省）に従う必要がある。

2015年の法改正以降、**医師1名の小規模クリニックであっても個人情報保護法の義務対象**となっており、すべての医療機関が適用を受ける。

### クラウドに音声データをアップロードする際の注意点

クラウドサービスへの外部保存を委託する場合は、**3省2ガイドラインを遵守した事業者を選定すること**が義務付けられている。

#### 3省2ガイドラインとは何か

「3省2ガイドライン」とは、以下の2つのガイドラインを総称したものを指す。

1. **「医療情報システムの安全管理に関するガイドライン」第6.0版（令和5年5月、厚生労働省）**
   - 医療機関自身が守るべきセキュリティルールを規定
   - 電子カルテや音声データなどの医療情報の管理・保管方法を定める

2. **「医療情報を取り扱う情報システム・サービスの提供事業者における安全管理ガイドライン」第1.1版（令和5年7月、総務省・経済産業省）**
   - クラウド事業者など、医療情報を扱うITサービス会社が守るべきルールを規定
   - クラウドサービスを使う際の責任分界点（医療機関とベンダーどちらが何を管理するか）を明確化

2023年の改定では、マイナ保険証の普及に伴うセキュリティ強化と、ゼロトラストセキュリティの概念拡充が重要な変更点となっている。

### 実務上の課題

音声データをクラウドにアップロードする場合、以下の点を事前に確認する必要がある。

- そのクラウド事業者が3省2ガイドライン対応を表明しているか
- データが国内リージョンに保存されるか、または海外への転送がないか
- AIモデルの学習データとして音声が使われないか（利用規約の確認）
- 録音した音声を後から削除できる仕組みがあるか

## 3. AWSの医療分野向けサービスと日本リージョンの活用事例

### AWS の医療向けサービス体系

AWS は医療機関向けに以下のサービスを提供している。

| サービス名 | 概要 |
|---|---|
| Amazon Transcribe Medical | 医療特化の音声文字変換API。医薬品名・疾患名・処置名などの専門用語に対応 |
| Amazon Comprehend Medical | 文章から患者情報・診断名・薬剤名などを自動抽出するNLPサービス |
| AWS HealthLake | FHIR（医療情報の国際標準フォーマット）に対応した医療データ管理サービス |
| Amazon Health AI | 医療分野向けの生成AIソリューション群 |

### Amazon Transcribe Medical の重要な制約

**現時点（2025年）において、Amazon Transcribe Medical は英語のみの対応となっている。**

これは日本の病院が AWS の医療音声認識を直接活用する際の大きな障壁である。一方で、汎用の Amazon Transcribe は日本語に対応しているため、日本の医療機関が AWS で音声認識を使う場合は汎用版を利用し、その後に医療用語辞書やカスタム言語モデルを適用して精度向上を図る運用が一般的となっている。

### 日本リージョンでの医療機関導入事例

**国立循環器病研究センター（大阪府）**
オンプレミス運用からAWSクラウドへIT基盤を刷新。医療データの統合管理と可用性向上を実現した。

**小原病院（医療法人厚生会）**
AWS を活用した遠隔地バックアップを実現。ランサムウェア対策も兼ねたBCP（事業継続計画）強化。

**浜松医科大学**
静岡県全体の医療連携を目的にAWSベースのデータプラットフォームを構築。「電子カルテ情報共有サービス」のモデル事業として稼働予定。

**東芝メディカルシステムズ（現キヤノンメディカルシステムズ）**
2012年からX線・CT・MRIなどの画像データをAWSベースで医療機関に提供するクラウドサービスを展開。国内では最初期のAWS医療活用事例のひとつ。

### 医療機関向けAWS利用リファレンス

AWSとNECなど複数のAPNパートナーが共同で「医療情報システム向けAWS利用リファレンス」を策定・公開している。これは3省2ガイドラインへの対応方法をAWS環境で具体的に解説したもので、医療機関がAWSを安心して導入するための指針となっている。

## 4. 音声認識の医療用語精度の問題

### なぜ医療現場での音声認識は難しいのか

音声認識の精度は、日常会話ではかなり高い水準に達しているが、医療現場では以下の理由から精度が落ちやすい。

#### 専門用語と略語の問題

- 「BP（血圧）」「SpO₂（酸素飽和度）」「BUN（尿素窒素）」などの略語
- 診療科ごとに異なる専門用語（循環器科・消化器科・整形外科それぞれで独自の用語体系）
- 薬剤名（「ランソプラゾール」「エソメプラゾール」など）の類似した音の聞き分け
- カタカナ英語の混在（「エコー」が心臓超音波を指すか音響現象を指すかは文脈次第）

#### 誤認識の具体例（医療以外の事例を含む）

AI議事録ツールで報告されている代表的な誤認識パターン：

- 人名の誤認識：「加藤さん」→「佐藤さん」、「ガラスさん」（架空の名前への変換）
- 業務用語の誤認識：「相手統制」→「IT統制」、「コース金額」→「工数金額」
- 医療用語では薬剤名や処置名が一般的な単語に誤変換されるリスクがある

これらの誤りが医療記録に混入した場合、**患者安全に直結する重大なリスク**となるため、医療現場では「AIの出力をそのまま使わず、必ず人間が最終確認する」ことがガイドラインでも求められている。

### 医療特化システムの対応策

**AmiVoice シリーズ**は、医療分野に特化した音声認識エンジンとして以下の対応を行っている。

- 診療科別の専門用語辞書（内科・外科・放射線科など）をあらかじめ搭載
- ユーザーが独自の用語を辞書に追加可能（病院名、医師名、院内独自の手順名など）
- 「薬剤名」「疾患名」「処置名」の区別を文脈で判断するモデルを採用

**厚生労働科学研究（研究代表者の取り組み）**
「電子カルテと連携する音声認識システムのニーズ把握及び音声認識システムに用いられる医療用語辞書の編纂に関する研究」（厚生労働科学研究成果データベース）として、医療用語辞書の整備が国レベルで進められている。

研究の知見として、医師と患者の会話には「難解な医学用語よりも一般語が多い」ことが分かっており、患者向けの説明場面（IC）での音声認識精度は比較的高い。一方で、医師同士のカンファレンスでは専門用語が飛び交うため精度が下がりやすい。

### Google Cloud の医療モデル

Google Cloud Speech-to-Text は専用の「Medical Models」を提供しており、以下に対応している。

- 診断名・治療法・疾患名・症状名を認識するようにカスタマイズされたモデル
- 医療環境で一般的な語彙に最適化された言語モデル
- 英語が主体だが、日本語対応の拡充も進んでいる

## 5. 現場スタッフの抵抗感・変化への心理的障壁

### 抵抗感の主な原因

医療機関で音声認識AIの導入が進まない、または現場定着しない理由として、以下が報告されている。

#### 操作習熟への不安

医師・看護師は日常業務が非常に忙しく、新しいシステムを習得する時間を確保しにくい。特に高齢の医療従事者が多い施設ではデジタルツールへの抵抗感が強い。

「ゆっくり・大きな声で喋らないと認識できない」という初期世代の音声認識への印象が残っており、新世代のAIシステムへの信頼獲得が課題となっている。

#### 「自分の発言が記録される」ことへの心理的負荷

音声認識が導入されると、会議での発言やカンファレンスの内容が自動的に記録・テキスト化される。これにより：

- 発言が後から「証拠」として残ることへの抵抗
- 「いつもより慎重に話さなければならない」という緊張感
- ミスや不正確な発言が記録に残ることへの恐れ

#### 誤認識への不信感

音声認識の誤変換を経験したスタッフは、AIへの信頼を失いやすく、修正作業が増えると「手書きのほうが早い」という評価になりやすい。

特に初期導入直後に精度が低い体験をすると、定着率が大幅に下がることが報告されている。

#### 組織文化・権威構造の問題

日本の病院は医師を頂点とするヒエラルキーが強い文化を持つ傾向がある。院長や部長が率先してツールを使わない場合、スタッフが積極的に活用しない構造が生まれやすい。

### 導入成功に向けた対策

成功した医療機関が取っている共通のアプローチ：

1. **小さな成功体験の共有**：まず一部の科やユニットで試験導入し、効果を数値で示す
2. **率先垂範**：経営層・管理職が自ら使い方を習得し、現場に見せる
3. **段階的研修**：ITリテラシーの個人差に配慮した個別サポート体制の構築
4. **修正コストの可視化**：「手で書くより早い」ことをデータで示す
5. **全員参加型の意識啓発**：「なぜ導入するか」を丁寧に説明し、現場スタッフを検討段階から巻き込む

## 6. 具体的な導入成功事例と失敗・課題事例

### 成功事例

#### 放射線科でのレポート作成（複数施設）

- **成果**：キーボード入力時に比べてレポート作成時間が1/5〜1/10に短縮
- **成功要因**：放射線レポートは定型文・定型フォーマットが多く、音声認識との相性が良い。記載内容も比較的パターン化されており、誤認識があっても修正箇所が分かりやすい

#### ヨコクラ病院（九州）

- **成果**：ICなどの記載業務効率が33%向上（Google Gemini活用）
- **成功要因**：患者への説明という比較的ゆっくり・明瞭な発話場面で音声認識を活用

#### 九州大学病院

- **成果**：入院サマリー作成の効率が54%向上（Google Gemini活用）
- **成功要因**：定型的な書類作成に特化した用途を選定。生成AIによる要約・標準化も組み合わせた

#### 東京の病院（医師・患者会話カルテ化）

- **成果**：カルテ記録時間が60%以上削減（NHK・海外報道より）
- **成功要因**：数千時間の対話データで学習したAIモデルを使用。音声入力とAI要約の組み合わせ

#### Medimo（全国150以上の医療機関）

- **成果**：カルテ入力時間が8割以上削減（2024年4月時点）
- **成功要因**：診察場面の会話を自動でカルテ形式に整形する専用AIで、汎用音声認識より精度が高い

### 課題・失敗に関わる報告

#### 誤認識による修正作業の増加

一般的な議事録AIで報告されている失敗パターン（医療機関でも同様の問題が生じうる）：

- 出席者の名前が頻繁に誤認識され、チームにいない人物の名前が出力される
- 業務用語が一般的な同音の単語に置き換えられる
- 複数人が同時に話した部分の精度が著しく低下する

#### 普及のボトルネック：電子カルテとの連携問題

日本の電子カルテシステムは、ベンダーロックインが強く、外部の音声認識サービスとのAPI連携が困難なケースが多い。電子カルテ側の対応が必要なため、病院単体での導入判断ができないことが普及を遅らせている。

#### 医療用語辞書のメンテナンスコスト

専門用語辞書を搭載した音声認識システムでも、新薬の承認・手術手技の変化・新たな略語の登場に追いつくための辞書更新作業が必要で、この維持コストが中小規模の医療機関には負担となっている。

## まとめ：日本の医療現場における音声認識AIの現在地

| 項目 | 現状評価 |
|---|---|
| 電子カルテ音声入力の普及 | 大病院を中心に急速に拡大中 |
| 議事録・カンファレンス記録への活用 | 試験導入・実証段階が中心 |
| AWS Transcribe Medical（日本語） | 現時点では英語のみ対応、汎用版で代替 |
| Azure Speech Services（医療用途） | 汎用音声認識として活用可能、医療特化は限定的 |
| Google Cloud Medical Models | 英語中心だが医療向けモデルを提供、Geminiが日本語に強い |
| 個人情報保護の整備状況 | 3省2ガイドラインで枠組みあり、運用は各機関次第 |
| 現場スタッフの定着率 | 成功施設と頓挫施設の差が大きい |

**最大の課題は「精度・セキュリティ・電子カルテ連携・人的障壁」の4つが複合していること。** どれか一つを解決しても、他が障壁になって導入が進まないケースが多い。
