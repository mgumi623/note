# 電子カルテシステムのネットワーク構成

病院の電子カルテ（EMR: Electronic Medical Record）を支えるネットワークは、患者の命に直結する情報を扱うため、一般企業のITインフラとは大きく異なる設計思想で構築されています。本レポートでは、閉域網、VPN、ファイアウォール、ネットワーク分離の4つの観点から、病院ITインフラの全体像を整理します。

---

## 1. 閉域網（クローズドネットワーク）の仕組み

### 1-1. 閉域網とは何か

閉域網とは、**インターネットから物理的または論理的に切り離されたネットワーク**のことです。一般のインターネットを経由しないため、外部からの不正アクセスやサイバー攻撃のリスクを大幅に低減できます。

医療機関で閉域網が使われる理由は明確です。電子カルテには患者の氏名・住所・病歴・検査結果・遺伝子情報など、極めてセンシティブな個人情報が含まれています。これらの情報がインターネット経由で漏洩すれば、患者への被害は甚大です。そのため、厚生労働省の「医療情報システムの安全管理に関するガイドライン 第6.0版」（2023年5月公表）でも、ネットワーク分離による境界防御が基本方針として示されています。

### 1-2. 病院内LANの3系統分離

日本の病院では、院内ネットワークを**3つの系統に分離する構成**が標準的です。これは「三層分離」とも呼ばれます。

#### (1) HIS系（医療情報系）ネットワーク

HISとは「Hospital Information System（病院情報システム）」の略で、病院の基幹業務を担うネットワークです。

- **接続されるシステム**: 電子カルテ、オーダリングシステム（医師が検査や投薬を指示するシステム）、医事会計システム（診療報酬の計算を行うシステム）、薬剤管理システム、検査システム、放射線情報システム（PACS）など
- **特徴**: インターネットから完全に分離されている。最も高いセキュリティレベルが求められる
- **扱う情報**: 患者の診療データ、検査結果、処方情報など

#### (2) 情報系（事務系）ネットワーク

病院の一般業務に使われるネットワークです。

- **接続されるシステム**: メール、グループウェア、事務用PC、経営管理システムなど
- **特徴**: 制限付きでインターネットに接続可能な場合がある。HIS系とは分離されている
- **扱う情報**: 事務連絡、経営データ、人事情報など

#### (3) インターネット系ネットワーク

外部との通信を行うネットワークです。

- **接続されるシステム**: Webブラウジング用端末、患者向けWi-Fi、外部メールなど
- **特徴**: インターネットに直接接続される。HIS系・情報系とは完全に分離
- **扱う情報**: 一般的なインターネット通信

この3系統を物理的または論理的に分離することで、たとえインターネット系がサイバー攻撃を受けても、電子カルテのあるHIS系には到達できないように設計します。

### 1-3. 通信事業者の閉域網サービス

複数の病院間でデータを共有する場合や、クラウド型電子カルテを利用する場合には、通信事業者が提供する閉域網サービスが利用されます。

#### NTT東日本・西日本の閉域網サービス

| サービス名 | 特徴 | 用途 |
|---|---|---|
| **フレッツ・VPNワイド** | NTTのフレッツ網内で完結する閉域VPNサービス。インターネットを経由しない | 病院の拠点間接続（本院と分院の接続など） |
| **フレッツ・VPNプライオ** | 帯域優先制御が可能なIP-VPN。通信品質を保証 | リアルタイム性が求められる医療画像の転送など |
| **フレッツ・VPNアドバンス**（2025年提供開始） | 最大10Gbps対応のマネージドVPN。UTM機能を含むセキュアプランあり | 大規模病院の高速閉域ネットワーク |
| **フレッツ・SDx**（NTT西日本） | 閉域IP-VPNにSD-WAN機能を統合。遠隔管理が可能 | 複数拠点を持つ医療法人の統合ネットワーク管理 |

#### KDDI

| サービス名 | 特徴 |
|---|---|
| **KDDI Wide Area Virtual Switch（KDDI WVS）** | 全国規模の閉域ネットワークサービス。拠点間をレイヤ2/レイヤ3で接続可能 |
| **ビジネスmoperaアクセスプレミアム** | モバイル通信でも閉域網を実現。訪問診療など院外からの安全なアクセス用途 |

これらのサービスは、データが通信事業者の閉域網内だけを通るため、インターネットを経由するVPNと比較してセキュリティが高いとされています。ただし、コストは通常のインターネット接続よりも高額になります。

### 1-4. オンプレミス型とクラウド型電子カルテの違い

電子カルテのサーバーをどこに置くかによって、ネットワーク構成は大きく変わります。

#### オンプレミス型（院内設置型）

**仕組み**: 病院の院内にサーバー室を設け、そこに電子カルテサーバーを設置します。データはすべて院内に保管されます。

**ネットワーク構成の特徴**:
- サーバーとクライアント端末は院内LANで直接接続
- インターネットへの接続が不要なため、完全な閉域網で運用可能
- サーバーの冗長化（メインサーバーとバックアップサーバーの二重化）は病院自身が行う
- バックアップ先として、同等スペックのサブサーバーやNAS（ネットワーク接続ストレージ）を配置

**メリット**:
- カスタマイズの自由度が高い（病院固有の運用に合わせた設定が可能）
- インターネット障害の影響を受けない
- データが院外に出ないため、情報漏洩リスクを低く保てる

**デメリット**:
- 初期費用が高額（大規模病院で数千万円～数億円）
- サーバーの保守・運用に専門の技術者が必要
- 災害時に院内のサーバーごと被災するリスクがある
- 5～7年ごとのシステム更新（リプレース）で大きな出費が発生

**主な製品**: 富士通「HOPE EGMAIN-GX」、NEC「MegaOakHR」、IBM「電子カルテシステム」など

#### クラウド型

**仕組み**: 電子カルテのサーバーをクラウド事業者（AWS、Azureなど）のデータセンターに配置し、病院からはネットワーク経由でアクセスします。

**ネットワーク構成の特徴**:
- 病院とクラウド間は閉域網またはVPN（後述）で接続
- データセンター側で複数リージョン（地域）にわたる冗長化が行われる
- 耐震構造や無停電電源を備えた専用データセンターで運用

**メリット**:
- 初期費用を大幅に抑えられる（月額課金制が多い）
- サーバーの保守・アップデートがクラウド事業者側で自動実行
- 災害時にもデータが複数拠点に分散保存されているためBCP（事業継続計画）に強い
- 端末を追加するだけで利用者を増やせる

**デメリット**:
- インターネット回線や閉域網に障害が発生すると電子カルテにアクセスできなくなる
- カスタマイズに制限がある
- 大規模病院ではランニングコストがオンプレミスより高くなるケースもある
- データが院外に出るため、セキュリティ基準への対応が必要

**主な製品**: エムスリーデジカル「デジカル」、CLINICS「クラウド電子カルテ」、Henryなど

#### 2025-2026年の動向

政府は、2025年度中を目途に標準型電子カルテの基本要件を策定し、2026年度中の完成を目指しています。クラウド・ネイティブな設計が前提とされており、今後はクラウド型への移行が加速する見通しです。

## 2. VPN（Virtual Private Network）の利用

### 2-1. VPNとは何か

VPN（仮想プライベートネットワーク）とは、インターネットなどの公衆回線上に**暗号化された仮想的な専用回線を構築する技術**のことです。物理的に専用線を引く代わりに、ソフトウェアの技術によってデータを暗号化し、あたかも専用線のように安全な通信を実現します。

病院では主に以下の3つの用途でVPNが使用されます。

### 2-2. 病院間接続でのVPN利用

複数の病院や診療所が同一の医療法人に属している場合、拠点間で電子カルテデータを共有する必要があります。このとき、各拠点のネットワークをVPNで接続します。

**具体的な利用シーン**:
- 本院と分院の電子カルテデータの同期
- 地域医療連携ネットワーク（複数の医療機関が患者情報を共有するネットワーク）
- 遠隔画像診断（放射線科医が遠隔地から画像を読影する仕組み）

### 2-3. リモートメンテナンス用VPN

電子カルテベンダー（富士通、NECなど）は、システムの保守・トラブル対応のために、病院のネットワークにリモートアクセスする必要があります。このとき、VPNを使って安全にアクセスします。

しかし、このリモートメンテナンス用VPNが**セキュリティ上の弱点**になることがあります。ベンダーがアクセスするための「入口」が、同時にサイバー攻撃者にとっての「入口」にもなり得るためです。

### 2-4. VPN機器の役割

VPN接続を実現するために、病院のネットワーク境界には**VPNゲートウェイ（VPN装置）**と呼ばれる機器が設置されます。

#### 主な製品

| 製品名 | メーカー | 特徴 |
|---|---|---|
| **FortiGate** | Fortinet（フォーティネット） | VPN機能とファイアウォール（後述）を統合。日本の医療機関で最も広く使われている。コストパフォーマンスに優れる |
| **Cisco ASA / Firepower** | Cisco Systems（シスコ） | 大規模ネットワーク向け。クラウド連携に強み |
| **Palo Alto PA シリーズ** | Palo Alto Networks | 高度なアプリケーション制御が可能。セキュリティ機能が充実 |
| **UNIVERGE IX** | NEC | 日本のネットワーク環境に最適化されたルーター/VPNゲートウェイ |

### 2-5. VPNが攻撃の入口になった事例

近年、日本の病院に対するランサムウェア攻撃（データを暗号化して身代金を要求するサイバー攻撃）の多くが、**VPN機器の脆弱性を突いて侵入**しています。

#### 事例1: つるぎ町立半田病院（2021年10月）

**被害の概要**: 徳島県の半田病院（120床）がランサムウェア「LockBit 2.0」に感染し、電子カルテが使用不能になりました。新規患者の受け入れ停止、手術の延期など深刻な影響が出ました。

**侵入経路**: VPN装置として使用されていた**FortiGate 60E**の脆弱性（CVE-2018-13379）が悪用されました。この脆弱性は2019年に発見・公表されていたにもかかわらず、約2年間にわたってファームウェアの更新が行われていませんでした。

**なぜ放置されたのか**: 調査報告書によると、VPN装置を納入したベンダーがセキュリティパッチ適用の重要性を病院に十分に説明しておらず、病院側にもIT専門人材がいなかったため、脆弱性情報が届かなかったとされています。報告書は「ベンダーが昨今のセキュリティ事情を考慮せず、極めて脆弱なシステムの販売と稼働を優先させた」と結論づけています。

**被害額**: 電子カルテシステムの再構築に約2億円。

#### 事例2: 大阪急性期・総合医療センター（2022年10月）

**被害の概要**: 大阪市の大規模病院（865床）がランサムウェア攻撃を受け、電子カルテを含む基幹システムの大部分が暗号化されました。外来診療や検査が停止し、復旧に73日間を要しました。

**侵入経路**: 攻撃者はまず、この病院に給食を委託していた業者（ベルキッチン）のVPN装置の脆弱性（CVE-2018-13379）を突いて給食業者のネットワークに侵入しました。次に、給食業者のネットワークと病院のネットワークが接続されていたため、**RDP通信**（リモートデスクトッププロトコル、PCを遠隔操作するための通信）を利用して病院内の栄養給食管理サーバーに侵入。さらに、サーバー間でID・パスワードが共通だったため、病院内の他のサーバーにも次々と侵入し、ランサムウェアを展開しました。

**問題点**:
- 給食業者のVPN装置の脆弱性が放置されていた
- 給食業者と病院のネットワークが適切に分離されていなかった
- 全サーバーのID・パスワードが共通で、全員に管理者権限が付与されていた
- 約2,200台の院内PCに不正アクセスの痕跡があった

**被害額**: NECなど3社から和解金（解決金）10億円。逸失利益は数十億円規模。

#### 事例3: 岡山県精神科医療センター（2024年5月）

ランサムウェア攻撃を受け、FortiOS 6.0.4に存在するSSL-VPN関連の脆弱性が悪用されました。

#### 事例4: 宇都宮セントラルクリニック（2025年2月）

ランサムウェア被害で最大約30万人分の個人情報が漏洩した可能性が公表されました。

### 2-6. VPNのセキュリティ対策の教訓

これらの事例から、VPN利用に関して以下の対策が不可欠であることがわかります。

1. **VPN機器のファームウェアを常に最新の状態に保つ**: 脆弱性が公表されたら速やかにパッチを適用する
2. **サプライチェーン全体のセキュリティを確認する**: 委託業者のネットワーク接続も適切に管理する
3. **認証を強化する**: 多要素認証（MFA）の導入、パスワードの使い回しを禁止する
4. **接続先を最小限にする**: VPN経由でアクセスできる範囲を必要最小限に制限する
5. **ログを監視する**: VPN接続のログを常時監視し、不審なアクセスを検知する

## 3. ファイアウォールの構成

### 3-1. ファイアウォールとは何か

ファイアウォール（FW）とは、ネットワークの境界に設置して、**許可された通信だけを通し、それ以外の通信を遮断する**セキュリティ機器のことです。「防火壁」という名前の通り、外部からの不正な通信がネットワーク内部に到達するのを防ぎます。

病院のネットワークでは、少なくとも以下の境界にファイアウォールが設置されます。

- インターネットと院内ネットワークの境界
- HIS系と情報系の境界
- DMZ（後述）と内部ネットワークの境界

### 3-2. 病院で使われるファイアウォール製品

UTM/ファイアウォール市場における主要メーカーのシェア（2024年時点）は以下の通りです。

| メーカー | 市場シェア | 特徴 | 医療機関での利用状況 |
|---|---|---|---|
| **Fortinet（FortiGate）** | 約34.7% | VPN・ファイアウォール・IPS等を統合。コストパフォーマンスが高い | 日本の医療機関で最も多く利用されている。小規模～大規模まで幅広いラインナップ |
| **Palo Alto Networks** | 約19.1% | アプリケーションレベルの通信制御に強み。高度な脅威検知機能 | 大規模病院やセキュリティ意識の高い施設で採用 |
| **Cisco Systems** | 約12.7% | クラウド連携に優れる。ネットワーク機器との統合管理が可能 | 大阪急性期・総合医療センターの復旧時にCisco製品を採用した事例がある |

#### 従来型ファイアウォールと次世代ファイアウォール（NGFW）の違い

- **従来型ファイアウォール**: IPアドレスとポート番号を基に通信の許可/遮断を判断。「どこから来た通信か」は制御できるが、「何の通信か」までは判断できない
- **次世代ファイアウォール（NGFW: Next-Generation Firewall）**: アプリケーションレベルで通信の内容を識別し、制御が可能。例えば「Webアクセスは許可するが、特定の危険なサイトへの通信は遮断する」といった制御が可能

### 3-3. DMZ（非武装地帯）の構成

DMZ（DeMilitarized Zone = 非武装地帯）とは、**外部ネットワーク（インターネット）と内部ネットワーク（院内LAN）の間に設けられる緩衝地帯**のことです。軍事用語から借用された名称で、外部と内部の両方からアクセスする必要があるサーバーを配置します。

#### DMZに配置される典型的なサーバー

- **Webサーバー**: 病院のホームページ、患者向け予約システム
- **メールサーバー**: 外部とのメール送受信を中継するサーバー
- **DNS サーバー**: ドメイン名の解決を行うサーバー（例：病院のドメイン名をIPアドレスに変換）
- **リバースプロキシ**: 外部からの通信を内部サーバーに中継するサーバー。外部からは内部サーバーの構成が見えなくなる
- **オンライン請求用端末**: 診療報酬のオンライン請求（レセプト請求）を行うための端末

#### DMZの構成パターン

**パターン1: シングルファイアウォール型**

1台のファイアウォールに3つのインターフェース（接続口）を設け、インターネット側・DMZ側・内部ネットワーク側をそれぞれ接続します。

```
[インターネット]
       |
  [ファイアウォール]---[DMZ: Webサーバー、メールサーバー等]
       |
  [院内ネットワーク]
```

- メリット: 機器が1台で済むため、コストを抑えられる
- デメリット: ファイアウォールのルール設定が複雑になる。1台が故障すると全体が停止する

**パターン2: デュアルファイアウォール型**

2台のファイアウォールの間にDMZを配置します。

```
[インターネット]
       |
  [外部ファイアウォール]
       |
    [DMZ]
       |
  [内部ファイアウォール]
       |
  [院内ネットワーク]
```

- メリット: セキュリティが高い（外部と内部を別のファイアウォールで防御）
- デメリット: コストが高い（機器2台＋管理の手間）

日本の病院での調査では、DMZを設置しているのは電子カルテ導入施設の**約22.5%**にとどまっており、500床以上の大規模病院では39.4%が設置しています。つまり、多くの中小規模病院ではDMZが未設置であり、セキュリティ上のリスクとなっています。

### 3-4. UTM（統合脅威管理）の利用

UTM（Unified Threat Management = 統合脅威管理）とは、**ファイアウォール、IDS/IPS（侵入検知/防御）、アンチウイルス、Webフィルタリング、迷惑メール対策など、複数のセキュリティ機能を1台の機器に統合したもの**です。

#### なぜ医療機関でUTMが有効なのか

- **専任のIT人材がいない**: 中小規模の病院にはIT専門のスタッフが不在のことが多く、複数のセキュリティ機器を個別に管理するのは困難
- **コスト制約**: 複数のセキュリティ製品を個別導入するよりも、UTM1台でカバーする方がコストを抑えられる
- **運用の簡素化**: 1つの管理画面から複数のセキュリティ機能を管理できる

#### UTMに含まれる主な機能

| 機能 | 説明 |
|---|---|
| **ファイアウォール** | 通信の許可/遮断を制御 |
| **IDS/IPS** | IDS（Intrusion Detection System）は不正な通信を検知して警告。IPS（Intrusion Prevention System）は検知に加えて自動で遮断 |
| **アンチウイルスゲートウェイ** | ネットワークを通過するファイルのウイルスチェック |
| **Webフィルタリング** | 危険なWebサイトへのアクセスを制限 |
| **迷惑メールフィルタリング** | スパムメールやフィッシングメールをブロック |
| **アプリケーション制御** | 特定のアプリケーションの通信を許可/遮断 |

#### クラウド型UTMの登場

最近では、UTM機能をクラウドサービスとして提供する「クラウド型UTM」も登場しています。初期投資を大幅に抑えられ、複数の拠点（病院・診療所）を一括管理できるため、複数拠点を持つ医療法人に適しています。NTT西日本の「フレッツ・VPNアドバンス」のセキュアプラン（2026年2月提供開始予定）などがこれに該当します。

### 3-5. ファイアウォールルール管理の実態と課題

病院のファイアウォールルール管理には、以下のような課題が存在します。

1. **ルールの複雑化**: 電子カルテ、医療機器、各種システムの通信要件が多岐にわたるため、ファイアウォールルールが数百～数千行に膨れ上がることがある
2. **「とりあえず許可」の蔓延**: 新しいシステムを導入するたびに通信許可ルールが追加されるが、不要になったルールの削除が行われない
3. **管理者の不在**: ファイアウォールの設定を理解している担当者がいなくなり、誰もルールの全体像を把握していない状態になる
4. **ベンダー任せ**: 設定変更をベンダーに依頼するケースが多く、病院側でルールの妥当性を検証できない

## 4. ネットワーク分離（セグメンテーション）

### 4-1. ネットワークセグメンテーションとは何か

ネットワークセグメンテーションとは、**1つの大きなネットワークを複数の小さなセグメント（区画）に分割し、セグメント間の通信を制御する**ことです。

これが重要な理由は、万が一1つのセグメントがサイバー攻撃を受けても、他のセグメントに被害が拡大するのを防げるためです。大阪急性期・総合医療センターの事例では、給食業者のネットワークと病院のネットワークが適切に分離されていなかったことが、被害拡大の主因でした。

### 4-2. VLAN（仮想LAN）構成

VLAN（Virtual LAN）とは、**物理的なLAN配線を変更せずに、ソフトウェアの設定だけでネットワークを論理的に分割する技術**です。

#### VLANの仕組み

通常、同じスイッチ（ネットワーク機器）に接続されたすべての端末は同じネットワークに属し、お互いに通信できます。VLANを設定すると、同じスイッチに接続されていても、異なるVLANに属する端末同士は直接通信できなくなります。

これにより、物理的にケーブルを引き直すことなく、ネットワークを柔軟に分割・管理できます。

#### 病院での典型的なVLAN構成例

```
VLAN 10: HIS系（電子カルテ、オーダリング）
VLAN 20: 医療機器系（CT、MRI、超音波等の画像診断機器）
VLAN 30: 情報系（事務用PC、メール）
VLAN 40: インターネット接続系
VLAN 50: ゲストWi-Fi（患者・来訪者用）
VLAN 60: VoIP系（IP電話、ナースコール）
VLAN 70: 監視カメラ系
```

#### VLAN間の通信制御

VLAN間の通信は、**レイヤ3スイッチ**（VLANをまたいだ通信を制御する機器）または**ファイアウォール**を経由させ、必要な通信だけを許可します。

例えば:
- VLAN 10（電子カルテ）→ VLAN 20（医療機器）: 検査結果の取り込みのため許可
- VLAN 50（ゲストWi-Fi）→ VLAN 10（電子カルテ）: 完全に遮断
- VLAN 30（情報系）→ VLAN 10（電子カルテ）: 原則遮断（必要な場合のみ限定的に許可）

#### VLAN関連の主な製品

| メーカー | 製品例 | 特徴 |
|---|---|---|
| **APRESIA Systems** | APRESIAシリーズ | 医療ネットワーク向けソリューションを提供。認証VLANに対応 |
| **Allied Telesis（アライドテレシス）** | ATシリーズ | 常滑市民病院など多数の導入実績。無線LAN統合管理に強み |
| **Panasonic（パナソニック）** | Zequoシリーズ | 病院向けネットワーク構成のリファレンスモデルを公開 |
| **YAMAHA（ヤマハ）** | SWXシリーズ | マルチプルVLAN機能でセグメント間の分離が容易 |
| **Cisco** | Catalystシリーズ | 大規模ネットワーク向け。マイクロセグメンテーション対応 |

### 4-3. 医療機器ネットワークの分離

医療機器（CT、MRI、人工呼吸器、輸液ポンプ、患者モニターなど）のネットワーク接続は、近年急速に増加しています。しかし、医療機器には以下のような特有のセキュリティ課題があります。

**医療機器ネットワークの課題**:

1. **OSが古い**: 多くの医療機器は組み込みOS（Windows XP、Windows 7など）で動作しており、セキュリティパッチの適用ができないことが多い
2. **更新が困難**: 医療機器は薬事法（医薬品医療機器等法）の認証を受けており、ソフトウェアの更新には再認証が必要になるケースがある
3. **長寿命**: 高額な医療機器は10～15年使用されることも珍しくなく、その間にセキュリティ環境は大きく変化する
4. **メーカーが限定的**: 医療機器のネットワーク設定はメーカーに依存しており、病院側で自由に変更できないことが多い

**対策: 医療機器専用セグメントの構築**

これらの課題に対応するため、医療機器を専用のVLANセグメントに配置し、以下のような制御を行います。

- 医療機器セグメントからインターネットへの直接通信を遮断
- 医療機器セグメントとHIS系（電子カルテ）の間は、必要な通信のみ（画像データの転送、検査結果の送信など）を許可
- 医療機器のリモートメンテナンス用通信は、専用のVPN経由で制御

**先進的なアプローチ: マイクロセグメンテーション**

従来のVLANによるセグメンテーションをさらに細分化し、**個々のデバイスレベルで通信を制御**する「マイクロセグメンテーション」という手法が注目されています。SDN（Software-Defined Networking = ソフトウェア定義ネットワーク）やNFV（Network Functions Virtualization = ネットワーク機能仮想化）の技術を活用し、ネットワークポリシーを自動的に適用します。

例えば:
- 心電図モニター → 電子カルテサーバーへの通信のみ許可
- CT装置 → PACSサーバー（画像保存システム）への通信のみ許可
- それ以外の通信はすべて遮断

### 4-4. 電子カルテサーバーの配置

電子カルテサーバーは、病院ネットワークの中で最も重要なサーバーであり、その配置には特別な注意が払われます。

#### オンプレミス型の場合の典型的な配置

```
[インターネット]
       |
  [ファイアウォール/UTM]
       |
    [DMZ]--- Webサーバー、メールサーバー
       |
  [ファイアウォール]
       |
  [コアスイッチ（レイヤ3）]
       |
  ┌────┼────┬────┬────┐
  |    |    |    |    |
VLAN  VLAN  VLAN VLAN VLAN
 10    20   30   50   60
 HIS  医療  情報 ゲスト VoIP
  |   機器
  |
[電子カルテサーバー]
[バックアップサーバー]
[データベースサーバー]
```

電子カルテサーバーは、HIS系VLAN内のサーバーセグメント（さらにVLANを細分化した領域）に配置されます。一般のクライアントPC（医師・看護師が使う端末）とは別のセグメントに置くことで、万が一クライアントPCがマルウェアに感染しても、サーバーへの直接的な攻撃を防ぎます。

### 4-5. ゲストWi-Fiと院内ネットワークの分離

入院患者や来訪者に提供するゲストWi-Fiは、院内の業務ネットワークとは**完全に分離**しなければなりません。

#### 分離の方法

1. **SSID（ネットワーク名）の分離**: 業務用SSIDとゲスト用SSIDを別々に設定
2. **VLAN タグによる論理分離**: 同じ無線APから発信されるSSIDでも、VLANタグを付与することで異なるネットワークに割り当て
3. **認証方式の違い**:
   - 業務用: IEEE 802.1X認証（デジタル証明書やRADIUS認証サーバーを使った強固な認証）
   - ゲスト用: Webポータル認証（ブラウザ経由で利用規約に同意するだけ）
4. **通信制御**: ゲスト用VLANからはインターネットへの通信のみ許可し、院内の他のVLANへのアクセスはすべて遮断
5. **SSIDの隠蔽**: 業務用SSIDはステルス設定（一般端末からSSID名が見えない状態）にし、登録済みの端末のみ接続可能にする

#### 実装上の注意点

- **帯域制御**: ゲストWi-Fiの通信量が増大して業務通信を圧迫しないよう、帯域を制限する
- **端末間通信の遮断**: ゲストWi-Fiに接続された端末同士の通信を遮断（プライバシー保護）
- **ログの取得**: 不正利用に備え、ゲストWi-Fiの接続ログを一定期間保存する

## 5. 厚生労働省ガイドラインの動向

### 5-1. 第6.0版の主なポイント

厚生労働省が2023年5月に公表した「医療情報システムの安全管理に関するガイドライン 第6.0版」では、従来の**境界防御型思考**（ネットワーク分離による防御）に加えて、**ゼロトラスト型思考**（すべてのアクセスを信頼せず、常に検証する考え方）が新たに取り入れられました。

ガイドラインは以下の4編で構成されています。

| 編 | 対象 | 内容 |
|---|---|---|
| 概説編 | 全員 | ガイドラインの全体像と基本的な考え方 |
| 経営管理編 | 経営層 | セキュリティへの経営的な意思決定と資源配分 |
| 企画管理編 | システム企画担当 | システム導入の計画段階で考慮すべき事項 |
| システム運用編 | システム運用担当 | 日常的な運用・保守で実施すべき対策 |

### 5-2. 境界防御からゼロトラストへ

従来の考え方は「院内ネットワークの内側は安全、外側は危険」という前提でしたが、実際には:
- 院内のPCがマルウェアに感染するケース
- 委託業者経由で攻撃が侵入するケース（大阪急性期・総合医療センターの事例）
- VPN機器自体が攻撃の入口になるケース（半田病院の事例）

などが発生しており、「内側＝安全」という前提が崩れています。ゼロトラストでは、院内・院外を問わず、すべてのアクセスに対して認証と認可を行い、通信を常時監視します。

## 6. まとめ: 病院ネットワークの全体像

```
[インターネット]
       |
 ┌─────────────────────────────────────────┐
 | [ファイアウォール / UTM]                 |
 |     |           |                        |
 |   [DMZ]    [VPN装置]                     |
 |  Web/メール  ├─ ベンダー保守用           |
 |              ├─ 拠点間接続               |
 |              └─ クラウド接続             |
 |                                          |
 | [コアスイッチ（L3）]                     |
 |     |                                    |
 |  ┌──┼──┬──┬──┬──┐                      |
 |  HIS 医療 情報 ゲスト VoIP               |
 |  系  機器 系   Wi-Fi  系                 |
 |  |   系   |     |     |                  |
 |  電子  CT  事務  患者  IP電話            |
 |  カルテ MRI PC   端末  ナースコール      |
 |  サーバー 等  メール   等                |
 |                                          |
 └─────────────────────────────────────────┘
```

病院ネットワークの安全性は、以下の多層的な防御策の組み合わせで確保されます。

1. **閉域網**: インターネットから切り離された専用ネットワークでデータを保護
2. **VPN**: 拠点間やリモートメンテナンスの通信を暗号化（ただし機器の脆弱性管理が不可欠）
3. **ファイアウォール/UTM**: ネットワーク境界で通信を制御し、不正アクセスを遮断
4. **ネットワークセグメンテーション**: VLANで院内ネットワークを分割し、被害の拡大を防止
5. **ゼロトラスト**: 境界防御だけに頼らず、すべてのアクセスを検証する新しいセキュリティモデル

しかし、現実には多くの病院でIT専門人材が不足しており、VPN機器のファームウェア更新やファイアウォールルールの管理が適切に行われていないケースが散見されます。半田病院や大阪急性期・総合医療センターの事例は、技術的な対策だけでなく、人材・体制・ベンダー管理を含めた総合的なセキュリティガバナンスの重要性を示しています。
