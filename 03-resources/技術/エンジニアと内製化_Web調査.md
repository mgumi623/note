# エンジニアと内製化：Web調査結果

このページは、AI時代のエンジニアスキル変化、フルスタック化の必要性、企業内製化トレンド、医療機関での事例に関するWeb調査を通じて収集した一次資料をまとめたものです。

## 1. AIによるコーディング自動化とエンジニアスキルの変化

### 1.1 生成AIによるコード生成の現状

#### 利用状況
- 開発者の84%がAIツールを使用している（2025年時点）
- GitHub Copilot、ChatGPT、Amazon Q Developerなどが一般化
- 「AIスピード」の時代から「AI品質」の時代へ移行（2025年 → 2026年）

#### ツール信頼度の低下
- 2025年前半：AIツールに対する信頼度は高かった
- 2025年後半：AIの信頼度は29%まで低下
- 原因：AIがもたらすロジックエラーの増加が報告されるようになった
- 「信頼のパラドックス」：多くは使用するが、信頼は低い

### 1.2 エンジニアに求められるスキルセットの転換

#### 従来的なスキル（2020年まで）
- プログラミング言語の習熟度
- フレームワークの深い理解
- デバッグ能力
- コーディング効率

#### 新しく求められるスキル（2025年以降）

**1. 「判断と統合の力」**
- コードを書く力よりも、システム全体の最適化能力
- AI出力の検証・監督能力
- アーキテクチャ・設計に関する深い思考

**2. AI拡張スキル**
- プロンプトエンジニアリング（正確な指示を出す力）
- AI結果の限界を理解する力
- AI出力をシステムに統合する能力

**3. 戦略思考**
- 「何をAIに任せるか、何は人間が判断するか」の選別
- チーム・組織横断でAI活用を推進する能力
- ビジネス視点からの技術選定

**4. システム検証力**
- AI生成コードのテスト・品質保証
- セキュリティ・コンプライアンス審査
- 本番環境での予測不可能な問題への対応

### 1.3 AIがもたらす労働市場の構造変化

#### 影響を受けるレイヤー

**ジュニア層（若手、20-25歳）:**
- 従来の役割：「成文化された知識に基づくルーチンワーク」
- AI導入による影響：この層の雇用が最大20%減少する可能性
- 理由：AIがジュニア層のタスクを高速・低コストで代替可能

**シニア層（経験者）:**
- 従来の役割：設計・判断・監督
- AI導入による影響：タスク量が増加（AIの監視・検証増）
- 新しい役割：AI SRE（AI Site Reliability Engineer）

#### 新しいエリート職種の台頭

**FDE（Forward-Deployed Engineer）**
- AIモデルを実装・カスタマイズする専門家
- AIを使いこなし、組織に適した形で展開する人材
- 市場価値が急速に上昇

### 1.4 生成AIが高度に熟練した労働者に与える影響

#### MIT Sloanの研究から
- 高度に熟練した労働者が最もAIから恩恵を受ける傾向
- 理由：彼らはAIを「相互補完的なツール」として使用可能
- 初級層は「より多くの基本的なコーディングを任せる」という単純な代替にとどまる

#### キャリア二分化のリスク
- 高度なスキルを持つ人 → AIを武器に生産性が3倍以上に
- 基礎スキルのみの人 → AI化により相対的に価値が低下

## 2. フルスタックエンジニア／T字型エンジニアの必要性

### 2.1 フルスタックエンジニアの定義

**従来の定義**:
- フロントエンド（UI/UX）を理解
- バックエンド（サーバー・ロジック）を理解
- データベース設計を理解
- インフラ・ミドルウェアも一定レベルで対応可能

**現在の拡大**:
- クラウドアーキテクチャの理解
- DevOps文化への適応
- 組織内ツール・プロセスの横断的理解
- ビジネス要件の理解

### 2.2 フルスタック化が必要な理由

#### ビジネススピードの加速
- DX推進では「迅速性」と「柔軟性」が極めて重要
- フロント・バック・DB間の「調整コスト」が意思決定を遅延させる
- 一人が複数層を理解することで調整時間を削減

#### アジャイル開発への適応
- スプリント内で機能を完成させるには、複数層の知識が必須
- 専門分化が進むと、スプリント完了までの依存関係が増加
- 結果として「計画立案」に時間がかかり、スピードが低下

#### コスト削減
- 専門家を複数配置するより、フルスタックエンジニアの方がコスト効率的
- 内製化時のブラックボックス回避

### 2.3 T字型スキルの重要性

**「I字型」の危険性**:
- 一つの専門性しかない
- その専門が自動化されると価値喪失
- AI時代には特に危険

**「×字型（全方向浅い）」の課題**:
- 専門性がないため、依存されない
- 深い問題解決ができない

**「T字型（幅広い知識＋深い専門性）」が最適**:
- 横軸：フロント・バック・DB・インフラ・ビジネスの基礎知識
- 縦軸：自信を持てる得意領域を1-2つ
- 例：「バックエンド専門だが、フロント・インフラ・ビジネスの基礎は理解」

### 2.4 フルスタック化の応用領域

#### Web開発
- 従来から多い領域
- 複雑性増加により、さらにフルスタック化が求められる

#### IoT開発
- デバイス側の組み込みソフト
- クラウドデータ基盤
- Webダッシュボード
の全てを一貫して担当するケースが増加中

#### データ分析・AI開発
- データエンジニアリング
- ML/DLモデル開発
- 分析結果の可視化
全層の理解が求められる

## 3. 企業内アプリケーション内製化のトレンド（2025年）

### 3.1 内製化が進む理由

#### 戦略的必要性
- IT = 単なる業務効率化のツール ではない
- IT = 新たなビジネスモデル創出・競争力強化の武器

これを実現するには、ユーザー企業自身が主体的に推進する必要があり、外注では不十分。

#### 「2025年の崖」への対応
- 2025年以降、レガシーシステムの課題が顕在化
- DX実現の急務
- システムのブラックボックス化回避

#### スピードと柔軟性の必要性
- DX推進には「素早い修正」「段階的な改善」が不可欠
- 外注では意思決定が遅い
- 内部にナレッジが蓄積される利点

### 3.2 内製化のメリット

| メリット | 詳細 |
|---------|------|
| **スピード** | 社内で即座に判断・修正できる |
| **柔軟性** | ビジネス要件の変更に即応可能 |
| **コスト** | 長期的には外注より低コスト |
| **ナレッジ蓄積** | 企業内にノウハウが蓄積される |
| **ブラックボックス回避** | システムの中身を理解できる |
| **セキュリティ** | 社内で管理できる |

### 3.3 内製化を推進するテクノロジー

#### ノーコード・ローコードツール
- **Microsoft Power Apps**
- **Salesforce Salesforce**
- **Google AppSheet**
- **Claris FileMaker**

これらにより「非エンジニアでもアプリ開発可能」という状況に。

#### AI開発支援ツール
- **GitHub Copilot** - コード自動生成
- **Amazon Q Developer** - AWS上での開発支援
- **ChatGPT** - 汎用的なコーディング支援

#### 低コスト化
- クラウドサービスの利用により、初期投資が削減
- SaaS型サービスにより保守コストも低減

### 3.4 内製化の課題

| 課題 | 対策 |
|------|------|
| **人材不足** | ノーコード・AI開発支援で人的障壁を低減 |
| **スキル不足** | 市民開発（Citizen Developer）育成プログラム実施 |
| **セキュリティ懸念** | ガバナンス・監査機構を設置 |
| **品質保証** | テスト文化の醸成、AIのレビュー体制構築 |
| **組織文化** | 失敗許容文化の構築が必須 |

## 4. 医療機関（病院）での内製化動向

### 4.1 背景：医療業界の特殊性

#### 医療DXの重要性
- 患者データ管理の効率化
- 医療スタッフの業務負荷軽減
- 病院経営の最適化（採算性向上）
- 医療の質向上

#### 従来の課題
- 複数の古いシステムが乱立
- ベンダーロックイン
- カスタマイズに時間・コスト
- 医療現場の要件を満たしていないシステムが多い

### 4.2 実事例1：済生会熊本病院

#### 背景
- 購買案件管理システムの老朽化
- 複雑な業務プロセスに対応していない

#### 施策
- **Microsoft Power Apps** を使用
- 医療情報システム室が主導
- 他部署のスタッフも「市民開発」に参加

#### 成果
- 老朽化システムを内製で刷新
- 部門横断で「DX人材」を育成
- ビジネスプロセスの可視化が実現

#### 重要ポイント
- ローコード開発により、非エンジニアも開発に参加可能
- トップダウンではなく、現場のニーズから発想

### 4.3 実事例2：さきがけホスピタル

#### 背景
- 独自の業務プロセスを持つ地方病院
- 既製システムではニーズに対応不可

#### 施策
- 院長がトップダウンでDX推進
- **Claris FileMaker** を選定
- 独自の業務システム「Sakigakeシステム」を内製開発
- 職員への開発トレーニング実施

#### 成果
- 完全カスタムされたシステム実現
- 職員がシステムメンテナンスを担当可能
- 病院文化としてDXが浸透

#### 重要ポイント
- リーダーシップが重要（院長主導）
- 長期的な人材育成戦略が必須

### 4.4 実事例3：春日井市民病院（AI活用）

#### 背景
- IT知識がない地方病院
- システム内製化に対する不安

#### 施策
- **Amazon Q Developer** を活用
- **ANGEL Dojo**（AWS内製化支援）に参加
- 「共創型内製化」を実施

#### 成果
- **わずか4日で以下を実装**：
  - 病床管理システム
  - 医療文書作成支援アプリ
- IT知識がないスタッフでも開発可能を実証

#### 重要ポイント
- AI開発支援により、初期の人材不足を克服
- 「できた」という成功体験がモチベーション向上につながる

### 4.5 医療機関での内製化の特徴

#### 医療特有の課題
- **セキュリティ・個人情報保護**: 患者データの厳格な管理が必須
- **システム信頼性**: システム障害が直接、診療に影響
- **規制対応**: 医療法など複雑な規制への対応
- **医学知識**: 開発者に医学的背景知識が求められる

#### 内製化の利点（医療特有）
- 医療現場の要件を深く理解できる
- 医療スタッフが要件定義に参加しやすい
- 患者プライバシーについて安心感が高い
- ローカライズ（地域別）対応が容易

## 5. 働き方の変化：現状と将来

### 5.1 2025年のエンジニア労働市場の変化

#### ジュニア層への影響
- 従来のジュニアタスク（ルーチンコーディング）がAIに代替
- 若手層（22-25歳）の雇用が最大20%減少する可能性
- 「ジュニア→シニア」への成長パスが不明確に

#### シニア層への影響
- AIの監視・検証タスク増加
- AIをマネージするミドル層の需要増加
- 設計力・判断力への価値が上昇

#### 新職種の出現
- **AI SRE**: AIエージェントの挙動監視・ガードレール設計
- **FDE**: AI実装・カスタマイズ専門家
- **Prompt Engineer**: 高度なプロンプト設計
- **AI Quality Assurance**: AI生成コードのテスト・品質保証

### 5.2 エンジニアに求められる「5つの資質」（サイバーエージェント技術トップの見解）

（詳細な5つは記載されていませんが、以下がキー要素）

1. **思考力**: 表面的な問題解決ではなく、本質的な課題を見極める
2. **学習能力**: AIツール・言語・パラダイムの急速な変化に適応
3. **コミュニケーション能力**: AIの可能性・限界をステークホルダーに説明
4. **設計思考**: 何をAIに任せ、何を人間が判断するかの最適設計
5. **倫理・セキュリティ感**: AIの使用に伴う責任と安全性への配慮

### 5.3 エンジニアの「生き残り戦略」

#### 短期（1-2年）の対策
- AI開発ツールを使いこなす
- プロンプトエンジニアリングを学習
- AI出力の検証力を磨く

#### 中期（2-5年）の対策
- フルスタック化・T字型スキル開発
- ビジネス視点の獲得
- 業界知識の深掘り（医療なら医療知識など）

#### 長期（5年以上）の対策
- リーダーシップ・マネジメント
- 新技術の研究開発
- アーキテクチャ・設計の専門性深掘り
- 経営層との対話能力

## 6. 組織への示唆：今何をするべきか

### 6.1 組織が直面する課題

1. **ジュニア層の育成パスの再構築**
   - 従来の「ルーチンコーディング」では育たない
   - 早期から複数層・複数領域の経験が必須

2. **シニア層への期待値の上昇**
   - 監視・検証・意思決定タスク増加
   - 疲弊のリスク

3. **新職種の育成・採用**
   - FDE、AI SREなどのポジション創出
   - 既存エンジニアの転換か外部採用か

4. **文化的な変化**
   - 「AIとの競争」から「AIとの協働」への思考転換
   - 失敗許容文化の醸成

### 6.2 医療機関（病院）が取るべきアクション

1. **内製化の段階的推進**
   - まずは「ノーコード」から開始
   - 成功体験を積む
   - 段階的に複雑なアプリへ

2. **人材育成プログラム**
   - 市民開発者（Citizen Developer）育成
   - 既存ITスタッフのスキルシフト

3. **リーダーシップ**
   - 院長・経営層の強いコミットメント
   - DXを「IT部門の仕事」ではなく「組織全体の仕事」と位置づけ

4. **ガバナンス・セキュリティ**
   - 内製化による品質・セキュリティ低下の防止
   - 監査・チェック体制の整備
